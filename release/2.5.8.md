# FindX 2.5.8 — official publish record

Baseline: 2.5.7. Incremental installer/fix release. Official packages are produced by GitHub Actions (`release.yml`) as a fresh three-platform rebuild after tag `v2.5.8`. They are not byte-identical to the local accepted setup (`FindX-2.5.8-setup.exe`, 12257060 bytes, SHA256 `9232941e3c567a3f2ae69ac58aaeecf5909aa297ca278ef580881559cc3218d3`).

## Applicable checks registered as passed (this release)

- `installer-live-handoff-from-2.5.5` (required): Live production started from running 2.5.5 GUI + service. Official installer was launched directly (`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`). GUI auto-exited, SCM stopped and saved, files installed, and the product restarted at 2.5.8. Timeline 2026-11-20 23:37:02-23:38:42 Asia/Shanghai. Evidence: local t247 result (`result=SUCCESS`).
- `legacy-2-4-multivolume-index-loads` (required, added post-publish): A real production 2.4.10 multi-volume store (E/D/C, 8.95M entries, 1.31M dirs, legacy flat v6 at generation 29213) previously failed to load with `ambiguous multi-volume root topology` and was rejected by installer Verify (`Stored index did not validate without fallback`, exit 1). After fix(core) 9056cb2: `findx2 status` loads v6 with exit 0 and no fallback keyword; `kernel32` search returns correct cross-volume paths (E:/D:/C:). Regression tests `crates/findx2-core/tests/legacy_multivolume_load.rs` pin flat-v6 load + three-volume resolution, v5/gen roundtrips, and the strict scoped path for new-format stores. Installer recovery fixes (e6eb104) un-wedge dead-transaction cleanup when the operator restarts the legacy service between attempts (graceful SCM stop instead of refusal) and stop the HKCU autostart compare from dead-locking rollback.
- `ps51-encoding-and-packaged-helpers` (required): Windows PowerShell 5.1 parse/import of receipt helpers required UTF-8 BOM on non-ASCII modules; official package must include all five scripts (`stop-mode.ps1`, `transaction-files.psm1`, `transaction-platform.psm1`, `transaction-receipt.psm1`, `upgrade-transaction.ps1`). RequestQuit staging copies that same helper set and preserves raw helper errors. Payload extract and native 5.1 preflight passed before the successful live install.
- `post-upgrade-search-paths-and-watch-health` (required): After the live upgrade, ntdll watch paths were preserved 5/5, `watch_error=null`, service `healthy=true`, published generation advanced (52288 to 52291).

## Explicitly not passed / not claimed

- `strict-protocol2-stop-receipt` (not required): SCM stop was Win32 1066 / specific 1, recorded as accepted partial save, not a strict protocol2 receipt. `metadata_ready` remained false.
- `legacy-gui-in-app-download-entry` (not required): The old GUI check-update/download-full-installer entry was not tested.
- `macos-linux-real-device-acceptance` (not required): macOS and Linux artifacts are CI-only; they were not accepted on real devices.

This record does not re-open or re-mark the 2.5.3 sealed engine P0 matrix (`v6-powerfail-and-persist-error-propagation`, etc.). Those tests were not repeated for 2.5.8.
