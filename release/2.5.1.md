# FindX 2.5.1 — trial publish of launch-experience fixes, gates still open

Baseline: 2.5.0. Patch increment so already-installed 2.5.0 can detect a newer release.

- Official FindX.exe uses the Windows GUI subsystem: normal product launches do not open a console. `--version` / `--help` attach or allocate a console only for those CLI paths.
- Official installed product window title, taskbar AppUserModelID, shortcut display, and PE ProductName are `FindX`. Distinctive `FindX Native (live)` / `FindX Native (isolated)` titles remain only for explicit development or fixture launches.
- Silent / very-silent upgrades always start `{app}\FindX.exe` after install, independent of leftover `postlaunch` checkedonce task state. Interactive installs keep the launch checkbox.
- Native login autostart continues to honor an existing HKCU Run value named `FindX` pointing at official `FindX.exe`. It is not enabled automatically for users who had it off.
- Workspace, package, PE, `--version`, and official Inno versions are unified at 2.5.1. Official packaging still requires `/DUpgradeGatesApproved=1` only to compile.

NOT approved as fully gated: power-loss / official-path upgrade and the other required gates in release/2.5.1.json remain `passed: false`. `publish_ready` stays false. See docs/UPGRADE-T158-LAUNCH-FIX.md.
