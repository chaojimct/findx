## What is implemented
Every tracked Activity can require a normal Result. Its outcome/error is published under the SAME Work mutex as the active-count decrement and wakeup. Therefore the actor cannot observe the last producer gone before its error exists. A missing completion and panic are fail-closed. Actual persister, metadata pipeline, per-watch iteration, before-spawn backfill/finalizer/trigram operations and queued-stat completion paths use these guards. Coalesced queued items explicitly transfer responsibility to the newer owned item; native stat tickets are released on partial IO, missing results and unwind, not just successful metadata commits.

The actor captures an outcome epoch and uses the SAME mutex to revalidate clean drain and publish its explicitly NON-ACK observation, sampling deadline/cancel/STOP again. A rejected publication sends an explicit error. Errors/cancel/STOP invalidate held observations. This does NOT implement a terminal IPC Commit receipt; positive durable_prepare remains false. Asynchronous cancel is observed by the actor; no unsupported claim that a blocking OS write is force-cancellable.

Recoverable persister errors clear ONLY after a real Ok(true) write from an activity admitted after that error; Busy/Ok(false), an older concurrent success and unrelated source successes cannot erase a newer/error source. Producer/metadata/stat errors remain retained until a proved source repair/restart; there is intentionally no blanket clear-on-heartbeat or clear-on-checksum. Failed prepare reopens non-stopping ingress for safe retry while retaining RAM and errors. STOP may drain with errors only to SAVE retained RAM; retained producer errors then propagate nonzero to SCM, rather than becoming a saved-and-healthy receipt. Failed final IO instead retains StopPending/RAM and retries, without force exit.

Negative versioned capability IPC now carries optional runtime_error. Older negative responses without it still decode. Old2.5.2 cannot acquire a new protocol by reinterpretation; unsupported final receipt remains refused. Existing source/client compatibility is preserved.
