# t115 transparent-root and bounded-pagination repair
2026-11-13 Asia/Shanghai. Local checkout, no deployment or active trial replacement.

## Verified cause, not missing scope
Read-only existing t114 pipe reproduced empty child pages with continuation and scope errors. A bounded streaming check of only the authorized mutable copy found the requested nested directory and public Users/Windows/Program Files directory records with live directory FileEntry owners. All descend through an empty-name physical NTFS root (record identity 5) under a synthetic volume sentinel. The old compact resolver treated this transparent component as a required visible path name.
The old build also linked tombstoned records; output max_bytes doubled as a work-scan budget, producing empty continuation pages. GUI stopped at the empty page. Legacy page_after walked sibling chains from their heads and ambiguously compared directory and FileEntry indices.

## Product change
- Empty-name root aliases use an existing DirAgg flags bit and normalize to the logical volume root. Files and directory children link directly into logical topology; raw IndexStore identities/parents remain unchanged. No extra per-file map, string or path copy. Root IO reuses the physical-root FileEntry FRN. Namespace moves, metadata and deletion deltas normalize parent identities too. A transparent alias does not count as another visible directory; bytes/files remain unchanged.
- Initial sibling chains omit tombstones. Opaque u32 continuation tokens retain independent dir/file positions in a fallibly allocated 1024-slot ring (its actual capacity charge is included in the runtime budget), scoped to root + epoch/generation. A continuation must include expected epoch/generation, preventing token reuse across process restarts. Cursor lookup is O(1), never a scan from the chain head or an ambiguous index. Wire shape and logical_tree=1 negotiation are unchanged. Expiration/out-of-scope/resource failure is explicit; refresh is required. The process-wide u32 token space is not reused; exhaustion requires restart, not silent wrap.
- Child-output charge (JSON-escaped name bytes + conservative fixed fields) is separate from a 64KiB internal traversal-work slice. Envelope/root health metadata are outside that child charge. A too-large single item returns an error requesting a larger page, never silently skips it. Continuation preserves all remaining work, with no corpus-sized cutoff.
- GUI asynchronously follows empty continuation pages, up to 16 per batch. It retains the final next cursor on yield, checks generation and repeated-token cycles, and checks cancellation before/after IO. Navigation/source changes revoke further paging; one already-in-flight IPC request may finish and be discarded. No renderer blocking, full materialization or infinite auto-pagination.
