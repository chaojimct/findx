# A2 authoritative-store fence: real durable evidence, NOT an installer ACK

Base2a5bbc0, 2026-11-19 Asia/Shanghai. Inherited CI44431909842 completed successfully, including actual service/IPC tests and refined-r4 GUI/CLI compilation. No old-code rerun.

## Product changes
- SearchEngine authoritative storage now uses one AdmissionStore instead of a directly exposed RwLock. EVERY existing core store.write path and the public mutable-store guard participates: namespace/cursor batches, metadata ticket/observation publication, overlay mirroring, replacement/compaction and raw callers. Already-admitted write guards drain; subsequent writers wait without discarding their RAM/payload. RAII reopens admission on error/cancel/timeout/abort.
- Guard release advances a conservative write-access sequence, including bookkeeping/no-op write accesses. It is NOT a USN, volume epoch, exact mutation count or on-disk format field; exhaustion refuses checkpoint evidence instead of wrapping.
- All three normal v6 publication entrypoints (full, delta, trigram generation) now share publication exclusion. A frozen checkpoint retains namespace and publication guards until abort/drop; it cannot become an unpinned checksum assertion.
- Frozen evidence is generated only by the real full v6 writer, while authoritative RAM remains locked. It carries an OS-random engine instance, exact caller nonce/version, canonical index identity, the coherent write-access sequence and the ACTUAL writer-returned published generation, checked against the published pointer. No RAM, dirty bitmap or pending mutation log is drained/cleared by the new API, on success OR failure. No index format changes.
- Pre/post-IO cancellation/deadline suppresses evidence. A generation already published before cancellation may remain complete/durable; that is explicitly NOT ACK or process-stop success. Blocking OS IO cannot be forcibly interrupted; deadline is checked again after it returns, not faked as cancellation-complete.

## Explicit hard boundary
The type is FrozenCheckpointEvidence, deliberately serializing upgrade_ack=false, runtime_drained=false, process_stopped=false, scope=frozen-authoritative-store-only. It is NOT exposed as a prepare/stop IPC response. Current UpgradeCapabilities continues durable_prepare=false. Published2.5.2 remains unable to acquire a new protocol, and must be refused before STOP.

Authoritative write admission/drain is NOT all runtime producer threads/persisters drained. Stat/backfill/finalizer/trigram worker handles and queued producer work still require service-level lifecycle registration/cancellation/join. A previously captured periodic batch can be waiting outside admission; its sequence/generation must be fenced or invalidated before it may publish after an aborted prepare. Service stop must not attempt to join producers blocked behind a still-held fence. Resume/overlay/exclusion sidecars and interprocess index ownership also need explicit complete-bundle handling. These are blockers BEFORE enabling any upgrade ACK, not N/A.

This batch intentionally does not wire normal SCM STOP/installer to the core-only evidence, which would falsely claim whole-runtime quiescence. Existing honest SCM error reporting does not yet prove failed STOP preserves every pending RAM value; the negotiated pre-STOP actor is still required. No force exit or process kill was added.
